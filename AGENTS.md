Bare `db.transaction` / direct `repo(db)` reads fail closed (0 rows/error) under least-privilege roles; today they work only because project roles still BYPASSRLS. Write repos that open their own `db.transaction` (invoice create/record/update, posting, quick-journal) must self-scope via `withOrg(orgId, …)` internally — never pass an outer tx into them (PgTransaction has no `.transaction`). ## Conventions
- **Money:** `numeric(18,2)` in DB, `Money` class BigInt minor via `Money.parseIdr`/`formatIdr` (`src/core/money/money.ts`) — never JS `number` for amounts.
- **Money across server actions (BUG MAGNET):** `Money.parseIdr` expects WHOLE rupiah — never feed it a minor-unit string (`bigint.toString()`), or amounts inflate 100×. Minor crosses the client→action boundary as digit-only strings (validate `/^\d+$/`); user-typed rupiah is parsed exactly once (client-side or action-side, never both).
- **AI decimal strings:** use shared `parseDecimalToMinor` (`core/money/money.ts`) — string/number decimal → minor, `null` when invalid; REJECTS zero/negative/3-decimals (fail-closed). Never `Number(x)*100` on nominal paths (1-sen drift, e.g. `1.005`). Explicit zero stays `0n` for free items / zero discount (don't route those through the helper).
- **Posting accounts:** never hardcode `4100`/`5100` as posting targets — they are GROUP (parent) accounts on onboarded COAs and fail guard `GROUP_ACCOUNT`. Always resolve via `resolveRevenueAccountId` / `resolveCogsAccountId` / `resolveExpenseAccountId` (`src/server/db/repos/accounts.repo.ts`; postable = !archived + childless, same predicate as `postingMetaMap`).
- **Posting:** `validate → post → immutable` — `journal_entries.status` DRAFT→POSTED only, trigger `forbid_posted_mutation` (`triggers.sql`), corrections via `reversal_of_id`, numbers `JE-YYYY-NNNN` year-scoped per org (`journals.repo.ts`: per-period `journal_seq_counters` + `pg_advisory_xact_lock`).
- **POS (kasir):** checkout posts ONE `postJournalEntry` (source `POS`: Dr Kas / Cr Pendapatan / Dr HPP / Cr Persediaan+links) + stock OUT via `applyCatalogStockOut` (`invoicing/posting.ts`) + ONE `kas_bank_entries` TERIMA log row pointing at that journal — never call `createCashEntryRepo` (double journal + PERSEDIAAN guard rejects). Tables `pos_shifts/sales/sale_items/sale_seq_counters` (`drizzle/0020`, sources `POS`/`POS_SELISIH` in `tax.sql` CHECK). Numbers `POS-YYYY-NNNN`, idempotency per submit.
- **AI:** `@google/genai` Interactions API (`src/server/ai/adapter.ts`, `nara.ts`, `journal-chat.ts`, `interaction-memory.ts`, model ids via `models.ts` — never hardcode at call sites), `store:true` + `previous_interaction_id` per thread (`chat_threads.gemini_interaction_id`, retry without chaining when stale), `response_format` JSON Schema + zod `DraftEntrySchema` (`schema.ts`), retry 2 (`MAX_RETRIES`). Anti-forget prompt rule: short confirmations ("ok catatkan ya") MUST resolve from last 12 messages (`advisor.ts:68`), never re-ask for details. Tool registry is single-source (`TOOL_REGISTRY` in `nara-tools.ts` — def+handler derived, never a second list). Uploads: ≤5MB (`src/server/storage/config.ts:MAX_DOCUMENT_BYTES`); allowed mimes are images + pdf + csv/txt/xls/xlsx (`ALLOWED_MIMES`), not arbitrary files.
- **Auth:** `@neondatabase/auth/next` client/server (`src/server/auth/*`); local `user` table is read-only identity mirror, sessions never live there.
- **UI:** Sidebar persisted `neraca:sidebar-collapsed`, topbar Cmd+K palette (`searchGlobalAction`). Shared patterns live in Reusable Components below — follow them instead of inventing.

## Testing Quirks
- `vitest.config.mts`: `fileParallelism:false` (integration files share one PG and TRUNCATE), `setupFiles:["tests/setup.ts"]` rewrites DB URL before any import. Run single file: `bunx vitest run tests/integration/ledger.test.ts`. `tests/unit/` covered too (`csv-import.test.ts` precedent). `TEST_CTX_ORG` seam (`auth/guard.ts`) lets tests call server actions directly as OWNER — no request scope needed.
- Storage tests skip when `SKIP_STORAGE_TESTS=1` or S3 unreachable (top-level probe).
- Playwright: `workers:1`, `reuseExistingServer:true` — kill stale `:3000` before `bun run e2e`; missing browser executable ⇒ `bunx playwright install chromium` (NOT a code failure); weed DOWN ⇒ 1 storage e2e skips, weed UP ⇒ 22/22. `tests/e2e/global-setup.ts` warms `/daftar /masuk /verifikasi /onboarding /dasbor` to avoid Turbopack cold-compile hydration race. After `goto`, wait `networkidle` + hydration before clicking or clicks land dead; keep `data-testid` contracts stable (`kasir-*`, `setoran-*`, `kas-bank-*`, `onboarding-*`) — specs depend on them. Long flows (signup+onboarding+aksi) exceed the 60s default — set `test.setTimeout(180_000)`; inside `toPass` polling use short inner timeouts (`textContent({timeout:3000})`), the 30s default eats the budget. Upload e2e: `setInputFiles` filePayload + storage-gated skip via direct `putDocument` probe (`kasir.spec.ts` precedent).
- Mocks of `@/server/db` in unit tests MUST include `transaction` passthrough (`db: { transaction: async (fn) => fn({ execute: async () => ({ rows: [] }) }) }`) or any page wrapped in `withOrg` throws `db.transaction is not a function`.
- Shell: PowerShell native; `weed:dev` needs `cmd /c`; plain `bash` is WSL — prefer `C:\Program Files\Git\bin\bash.exe -c` or PowerShell. Never `bash` heredoc for file writes.
